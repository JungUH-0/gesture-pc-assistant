# 기능명세서

| 항목 | 내용 |
|---|---|
| 프로젝트 | gesture-pc-assistant (손·포즈·음성으로 PC를 제어하는 개인 AI 비서) |
| 문서 기준일 | 2026-11-17 |
| 기준 코드 | `main` 브랜치 (커밋 ca68ca8 이후) |
| 실행 환경 | Windows, Python 3.10, 웹캠, 마이크, (Whisper용 NVIDIA GPU), Ollama |
| 작성 원칙 | 코드에 있는 값만 적는다. 임계값은 "실측 전"인 것과 조정이 끝난 것을 구분해서 표시한다 |

## 1. 상태 표기

| 표기 | 뜻 |
|---|---|
| 구현 | 코드가 있고 현재 기본값으로 동작 |
| 구현 (실측 전) | 코드가 있으나 임계값이 추정치라 조정이 필요 |
| 비활성 | 코드는 있으나 스위치로 꺼져 있음 |
| 예정 | 아직 코드 없음 |

## 2. 전체 구성

| 모듈 | 파일 | 역할 |
|---|---|---|
| 통합 실행 | `main.py` | 모든 모듈을 스레드로 실행, 모드 전환, 신호 통합, 명령 실행 연결, 콘솔 명령 등록 |
| 카메라(손) | `cameramodule.py` | 손 랜드마크 → 마우스·제스처 판정 (손 모드) |
| 포즈 | `posemodule.py` | 상체 랜드마크 → 끄덕임·가로젓기·자리 비움·ㅡ자 판정 (포즈 모드) |
| 오디오 | `audiomodule.py` | 박수 감지 |
| 음성 | `voicemodule.py` | 웨이크워드 감지, 명령 녹음, Whisper 변환 |
| 명령 | `commandmodule.py` | 자연어 → LLM 해석 → 명령 저장·실행 |
| PC 제어 | `windowcontrol.py` | 창·마우스·키·앱·URL 실행 (화이트리스트) |

인식 모드는 **손 모드와 포즈 모드 중 하나만** 켠다. 동시에 돌리면 FPS가 크게 떨어지고 제스처끼리 충돌하기 때문이다. 시작은 손 모드이다.

## 3. 기능 목록

### 3.1 손 모드 (손동작)

모든 판정은 손 한 개의 랜드마크를 기준으로 한다. 거리 값은 카메라 화면 기준 정규화 좌표(0~1)이다.

| ID | 기능 | 동작(사용자) | 판정 조건 | 결과 | 상태 |
|---|---|---|---|---|---|
| H-01 | 커서 이동 | 손을 움직임 | 손바닥 중심(손목+4개 MCP 평균)을 화면 좌표로 매핑. 중앙 70% 영역을 화면 전체로 확대(`CURSOR_ACTIVE_MARGIN` 0.15), 떨림 완화(`CURSOR_SMOOTHING` 0.5) | 마우스 커서 이동 | 구현 |
| H-02 | 좌클릭·드래그 | 엄지와 검지를 붙임 | 손바닥 방향(front)일 때만. 붙임 거리 < 0.05(`PINCH_ON_DIST`), 놓음 거리 > 0.08(`PINCH_OFF_DIST`) | 마우스 왼쪽 버튼 누름/뗌 (유지하면 드래그) | 구현 (실측 전) |
| H-03 | 우클릭 | 엄지를 손바닥 중심으로 접어 넣음 | 손바닥 방향일 때만. 엄지 끝-손바닥 중심 거리 < 0.035(`THUMB_TUCK_DIST`), 넣는 순간 1회 | 마우스 우클릭 | 구현 (실측 전) |
| H-04 | 휠 스크롤 | 약지·새끼를 말고 중지를 편 채 손 전체를 위/아래로 움직임 | 시작 시점 손바닥 중심 y를 기준점으로 기억, ±0.06(`WHEEL_HAND_MARGIN`) 이상 이동 시 0.12초 간격(`WHEEL_TICK_INTERVAL_SEC`)으로 반복 | 휠 업/다운 | 구현 |
| H-05 | 쓸어올리기 `swipe_up` | 손을 빠르게 위로 | 0.27초(`SWIPE_WINDOW_SEC`) 안에 손바닥 중심이 0.18(`SWIPE_Y_THRESHOLD`) 이상 위로 이동, 재인식 대기 0.6초 | 등록된 `swipe_up` 명령 실행, 없으면 마지막 창 복원 | 구현 |
| H-06 | 쓸어내리기 `swipe_down` | 손을 빠르게 아래로 | H-05와 같은 기준, 방향만 반대 | 등록된 `swipe_down` 명령 실행, 없으면 활성 창 최소화 | 구현 |
| H-07 | 창 닫기 확인 | 손날(손을 세움)로 쓸어내림 | 쓸어내리기 순간 또는 직전 0.3초(`EDGE_RECENT_SEC`) 안에 손날 판정. 손날 판정: 사잇각 sin 값 < 0.28 진입, > 0.42 이탈(히스테리시스) | "창을 닫을까요?" 확인 시작 (5초 안에 응답, 아래 H-08/P-01/P-02). 예 → 등록된 `close_confirm` 명령, 없으면 활성 창 닫기. 아니오·무응답 → 취소 | 구현 |
| H-08 | 예 / 아니오 | 주먹을 쥐고 엄지를 위(예) 또는 아래(아니오) | 검지~새끼 4개가 모두 말림, 엄지 끝이 손바닥 중심보다 0.08(`THUMB_UPDOWN_Y_MARGIN`) 이상 위/아래, **1.0초 유지**(`THUMB_UPDOWN_HOLD_SEC`) | 예/아니오 신호. 닫기 확인 중이면 응답으로 사용 | 구현 |
| H-09 | 커스텀 슬롯 3개 | 엄지를 중지 / 약지 / 새끼에 붙임 | 손바닥 방향일 때만. 붙임 < 0.05, 뗌 > 0.08, 0.1초 유지(`PINCH_SLOT_HOLD_SEC`) | 슬롯 이름(`pinch_middle` / `pinch_ring` / `pinch_pinky`)으로 등록된 명령 실행. 없으면 안내 로그만 | 구현 (실측 전) |
| H-10 | 음성 명령 시작 | 손등을 카메라에 보인 채 3초 유지 | 손등 판정 유지 3.0초(`VOICE_TRIGGER_HOLD_SEC`) | 음성 명령 녹음 시작. 손등 자세를 풀면 녹음 종료 (무전기 방식) | 구현 |
| H-11 | 모드 전환 | 양손을 모아 1초 유지 | 손 모드: 두 손 중심 거리 < 0.15(`HANDS_TOGETHER_THRESHOLD`). 유지 1.0초(`MODE_SWITCH_HOLD_SEC`), 전환 후 1.5초(`MODE_SWITCH_COOLDOWN_SEC`) 동안 재전환 금지, 손을 떼야 다시 전환 가능 | 손 모드 ↔ 포즈 모드 전환 | 구현 (실측 전) |

**방향 판정 규칙**: 손은 손바닥(front) / 손등(back) / 손날(edge) 중 하나로 판정한다. 손날일 때는 엄지 기반 클릭류(H-02, H-03, H-09)와 엄지척/다운(H-08)을 판정하지 않는다. 손날로 전환하는 과정에서 클릭이 튀는 오인식을 막기 위해서이다. 왼쪽 버튼을 누른 상태(드래그)이거나 휠 자세일 때는 스와이프를 판정하지 않는다.

### 3.2 포즈 모드 (상체)

MediaPipe Pose(BlazePose)를 사용한다. 포즈 모드에서는 손 추적이 꺼져 있어 마우스 제어(H-01~H-04)는 동작하지 않는다. 거리 값은 어깨 너비 대비 비율이다.

| ID | 기능 | 동작(사용자) | 판정 조건 | 결과 | 상태 |
|---|---|---|---|---|---|
| P-01 | 끄덕임 (예) | 고개를 두 번 끄덕임 | 최근 2.0초(`HEAD_WINDOW_SEC`) 안에 방향 전환 4회 이상(`HEAD_MIN_SWINGS`). 세로 진폭 ≥ 0.06(`HEAD_PITCH_MIN_SWING`) 어깨 너비 대비. 가로 방향 전환은 1회 이하(`HEAD_OTHER_MAX_SWINGS`), 세로 진폭이 가로 진폭의 1.5배 이상(`HEAD_DOMINANCE_RATIO`). 인정 후 1.0초 대기(`HEAD_EVENT_COOLDOWN`) | 예 신호. 등록된 `nod` 명령 실행(닫기 확인 중에는 응답으로만 사용) | 구현 (실측 전) |
| P-02 | 가로젓기 (아니오) | 고개를 두 번 좌우로 저음 | P-01과 같은 구조, 가로 진폭 ≥ 0.25(`HEAD_TURN_MIN_SWING`), 세로 방향 전환 1회 이하 | 아니오 신호. 등록된 `shake` 명령 실행(닫기 확인 중에는 응답으로만 사용) | 구현 (실측 전) |
| P-03 | 자리 비움 / 복귀 | 카메라에서 벗어남 / 돌아옴 | 사람이 5.0초(`AWAY_AFTER_SEC`) 이상 안 보이면 자리 비움, 다시 보이면 복귀 | 등록된 `away` / `back` 명령 실행. 없으면 로그만 | 구현 (실측 전) |
| P-04 | 화면 캡처 | 양팔을 옆으로 뻗어 ㅡ자로 유지 | 손목·팔꿈치가 어깨 높이에서 0.4 이내(`T_POSE_MAX_HEIGHT`), 손목이 어깨보다 바깥으로 1.0 이상(`T_POSE_MIN_REACH`), 1.0초 유지(`T_POSE_HOLD_SEC`), 캡처 후 3.0초 대기(`T_POSE_COOLDOWN_SEC`) | 전체 화면을 `captures/capture_날짜_시간.png`로 저장 | 구현 (인식 1회 확인, 임계값 실측 전) |
| P-05 | 모드 전환 | 양손을 모아 1초 유지 | 두 손목 거리 < 어깨 너비의 0.5배(`HANDS_TOGETHER_SHOULDER_RATIO`) | 포즈 모드 → 손 모드 (H-11과 동일 규칙) | 구현 |
| P-06 | 자세 분류 | 학습된 자세 이름 인식 | 22차원 특징 벡터는 추출 중이나 분류기 없음 | 자세 이름 표시 | 예정 |

**머리 판정(P-01, P-02)의 전제**: 어깨와 코·귀만 보이면 판정한다. 팔이 가려져도 동작한다.

### 3.3 음성

| ID | 기능 | 동작(사용자) | 판정 조건 | 결과 | 상태 |
|---|---|---|---|---|---|
| V-01 | 웨이크워드 감지 | "웨이크"라고 말함 (임시 단어) | 최근 3.0초 오디오를 1.5초마다 Whisper(`medium`, GPU `float16`)로 변환해 웨이크워드 포함 여부 확인. 녹음 중에는 검사하지 않음 | 명령 녹음 시작 (무음 감지 방식) | 구현 |
| V-02 | 명령 녹음 | 웨이크워드 뒤에 명령을 말함 | 무음 1.2초(`VAD_SILENCE_SEC`)이면 종료(웨이크워드 방식). 손등 방식은 자세를 풀면 종료. 최대 15초(`MAX_RECORD_SEC`), 0.3초 미만은 무시(`MIN_RECORD_SEC`). 말소리 기준 RMS > 0.02 | 녹음을 Whisper로 문장으로 변환 | 구현 |
| V-03 | 음성 명령 실행 | (V-02 이후 자동) | 변환된 문장을 LLM이 해석해 1회성으로 실행 (등록 없이). 별도 스레드로 실행해 제스처 처리가 멈추지 않음 | PC 동작 실행 (4절 표 참고) | 구현 |
| V-04 | 박수 감지 | 박수를 침 | 순간 음량(peak ≥ 0.12), 바닥값 대비 2.0배 이상, 고주파 대역(1500~7000Hz) 비율 ≥ 0.25 | 모드 전환 보조 신호 | 비활성 (모드 전환은 현재 박수 없이 양손 모으기로만 동작: `MODE_SWITCH_REQUIRE_CLAP = False`) |

### 3.4 명령 등록·실행

| ID | 기능 | 설명 | 상태 |
|---|---|---|---|
| C-01 | 명령 등록 | `이름: 하고 싶은 일`(자연어)을 입력하면 LLM(Ollama `qwen2.5:3b-instruct`)이 `{action, target}`으로 해석해 `commands.json`에 저장. 현재 입력 경로는 `main.py` 실행 중 콘솔뿐이다. 응답 대기 60초(`OLLAMA_TIMEOUT_SEC`) | 구현 |
| C-02 | 등록 명령 실행 | 제스처·포즈 이벤트 발생 시 이름으로 저장된 명령을 찾아 실행. 없으면 기본 동작이 있는 이벤트(`swipe_up`, `swipe_down`, `close_confirm`)는 기본 동작, 나머지는 로그만 | 구현 |
| C-03 | 자유 명령 즉시 실행 | 음성으로 말한 문장을 저장하지 않고 그 자리에서 해석·실행 (V-03) | 구현 |
| C-04 | 이름 검증 | 콘솔 등록 시 `main`이 호출하지 않는 이름이면 "저장만 되고 실행되지 않음" 경고 | 구현 |

**등록 가능한 이름 (main이 호출하는 이름)**

| 이름 | 발생 조건 | 기본 동작 |
|---|---|---|
| `swipe_up` | H-05 | 마지막 창 복원 |
| `swipe_down` | H-06 | 활성 창 최소화 |
| `close_confirm` | H-07 에서 "예" | 활성 창 닫기 |
| `pinch_middle` / `pinch_ring` / `pinch_pinky` | H-09 | 없음 |
| `nod` | P-01 | 없음 |
| `shake` | P-02 | 없음 |
| `away` | P-03 자리 비움 | 없음 |
| `back` | P-03 자리 복귀 | 없음 |

### 3.5 PC 제어 범위 (LLM이 쓸 수 있는 동작)

LLM은 시스템을 직접 건드리지 않는다. 아래 `action`과 화이트리스트에 있는 `target`만 `windowcontrol.py`가 실행하며, 목록에 없으면 거부한다.

| action | target | 허용 값 |
|---|---|---|
| `minimize_window` / `close_window` / `restore_window` | 없음 | - |
| `turn_off_monitor` / `turn_on_monitor` | 없음 | - |
| `open_app` | 필요 | chrome, edge, notepad, calculator, explorer, cmd, powershell |
| `press_shortcut` | 필요 | copy, paste, cut, undo, redo, save, select_all, new_tab, close_tab, switch_window |
| `press_media_key` | 필요 | volume_up, volume_down, mute, play_pause, next_track, prev_track |
| `open_url` | 필요 | youtube, google, gmail, naver, github |
| `search_web` | 필요(자유 텍스트) | 검색어. 구글 검색 주소로만 열리며 URL 인코딩과 길이 제한 적용 |

해석할 수 없거나 목록에 없는 요청은 `unknown`으로 처리해 실행하지 않는다.

### 3.6 신호 통합 (예 / 아니오)

| 신호 | 채널 | 상태 |
|---|---|---|
| 예 | 엄지척(H-08), 끄덕임(P-01), 눈 깜빡임 1회 | 앞의 둘 구현 / 눈 깜빡임 비활성 |
| 아니오 | 엄지다운(H-08), 가로젓기(P-02), 눈 더블 블링크 | 앞의 둘 구현 / 눈 더블 블링크 비활성 |

신호는 새로 켜지는 순간(rising edge)에만 한 번 반응한다. 같은 신호가 계속 True로 읽혀도 한 번만 처리한다.

### 3.7 시스템·진단

| ID | 기능 | 설명 | 상태 |
|---|---|---|---|

## 4. 데이터 입출력 요약

| 항목 | 위치 | 내용 |
|---|---|---|
| 등록 명령 | `commands.json` | `{이름: {action, target}}`. 개인 설정이라 Git 제외, 예시는 `commands.example.json` |
| 화면 캡처 | `captures/` | ㅡ자 자세 캡처 PNG. Git 제외 |
| 진단 로그 | `debug_*.txt` | Git 제외 |

## 5. 알려진 제약·미확인 사항

| 항목 | 내용 |
|---|---|
| 임계값 | "실측 전"으로 표시한 값은 추정치라 사용자·환경에 따라 조정이 필요 |
| GPU | Whisper가 `cuda`·`float16`으로 고정. NVIDIA GPU와 CUDA 환경이 없으면 모델 로딩 단계에서 실패할 수 있음 (CPU 폴백은 예정) |
| 프레임 | 이 PC 측정에서는 음성을 켜도 평균 FPS가 유지됨(29~31). 다만 순간 최저 6.4 FPS가 한 번 관측됨. 환경에 따라 끊김이 있었다는 보고가 있으나 원인은 미확인 |
| 웨이크워드 | "웨이크"는 임시 단어 |
| 폰트 | 한글 표시 폰트 경로가 Windows 기본 경로(`C:\Windows\Fonts\malgun.ttf`)로 고정 |
| 플랫폼 | Windows 전용 (`pywin32`) |
| 포즈 모드 | 손 추적이 꺼져 마우스 제어와 손 제스처가 동작하지 않음 |

## 6. 예정 기능 (UI 전환 계획)

| 항목 | 내용 |
|---|---|
| 트레이 앱 | 콘솔·카메라 창 없이 트레이 아이콘으로 상주 |
| 카메라 미리보기 | 랜드마크 점만 표시, 지표 없음, 트레이에서 켜고 끔 |
| 알림·팝업 | 토스트 알림, 창 닫기 확인 팝업 |
| 설정창 | 명령 등록 입력창(LLM 해석), 음성 켜기/끄기, 저장 폴더 등 |
| Whisper CPU 폴백 | GPU가 없을 때 작은 모델·`int8`로 전환 |

위 항목의 상세는 메뉴 구조, UI 명세서, 유저흐름도 문서에서 다룬다.

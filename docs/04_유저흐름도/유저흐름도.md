# 유저흐름도 (시나리오)

| 항목 | 내용 |
|---|---|
| 프로젝트 | gesture-pc-assistant |
| 문서 기준일 | 2026-11-17 |
| 기준 | 트레이 앱 **설계안**의 흐름. 현재(콘솔 + 카메라 창)와 다른 점은 시나리오 아래에 따로 적는다 |
| 관련 문서 | 기능명세서 (판정 조건·값), 메뉴 구조 (화면 구성) |
| 표기 | 사용자 행동 → 시스템 반응. 판정 값은 기능명세서의 ID(H-01 등)로 참조한다 |

## 1. 시나리오 목록

| ID | 시나리오 | 사용자 목적 |
|---|---|---|
| S-1 | 최초 실행 | 프로그램을 켜고 쓸 수 있는 상태까지 도달 |
| S-2 | 손으로 마우스 조작 | 마우스 없이 손으로 커서·클릭·스크롤 |
| S-3 | 명령 등록 | 제스처에 하고 싶은 일을 연결 |
| S-4 | 음성 명령 | 말로 PC 동작을 즉시 실행 |
| S-5 | 창 닫기 확인 | 실수 없이 창을 닫음 |
| S-6 | 포즈 모드 사용 | 몸 동작(끄덕임·가로젓기·ㅡ자)으로 조작 |
| S-7 | 자리 비움 / 복귀 | 자리를 비울 때 자동으로 동작 실행 |
| S-8 | 인식 상태 확인 | 설정이 제대로 인식되는지 확인 |
| S-9 | 일시정지 / 종료 | 인식을 잠시 멈추거나 프로그램을 끝냄 |
| S-10 | 오류 상황 | 카메라·Ollama·GPU 문제 시 대응 |

## 2. 시나리오별 흐름

### S-1 최초 실행

| 단계 | 사용자 행동 | 시스템 반응 | 화면 표시 |
|---|---|---|---|
| 1 | 프로그램을 실행 | Whisper 모델 로딩(수십 초 걸릴 수 있음), 카메라·마이크 시작 | 트레이 아이콘만 표시 |
| 2 | (대기) | 로딩 완료, 손 모드로 시작 | 토스트: "준비되었습니다" |
| 3 | 트레이 아이콘 우클릭 | 트레이 메뉴 표시 | 메뉴 5개 항목 |

최초 1회에는 Whisper 모델을 내려받아야 하고 Ollama가 설치되어 있어야 한다. 이 안내는 README에 둔다.

### S-2 손으로 마우스 조작 (손 모드)

| 단계 | 사용자 행동 | 시스템 반응 | 기능 ID |
|---|---|---|---|
| 1 | 손을 카메라에 보이고 움직임 | 손바닥 중심을 따라 커서 이동 | H-01 |
| 2 | 엄지와 검지를 붙임 | 왼쪽 버튼 누름 (유지하면 드래그) | H-02 |
| 3 | 엄지와 검지를 뗌 | 왼쪽 버튼 뗌 | H-02 |
| 4 | 엄지를 손바닥 쪽으로 접어 넣음 | 우클릭 | H-03 |
| 5 | 약지·새끼를 말고 중지를 편 채 손을 위/아래로 | 휠 스크롤 | H-04 |
| 6 | 손을 빠르게 위/아래로 쓸음 | 등록된 `swipe_up`/`swipe_down` 실행, 없으면 창 복원/최소화 | H-05, H-06 |
| 7 | 손을 내림 | 손이 안 보이면 인식 대기. 3초 이상 안 보이면 로그만 생략 | S-01 |

클릭류는 손바닥이 카메라를 향할 때만 동작한다. 손날로 세우면 클릭이 발동하지 않는다.

### S-3 명령 등록

| 단계 | 사용자 행동 | 시스템 반응 | 화면 표시 |
|---|---|---|---|
| 1 | 트레이 메뉴 → 설정 | 설정창 열림 | 설정창, 명령 등록 탭 |
| 2 | 동작 이름을 목록에서 선택 (예: `pinch_ring`) | 해당 이름의 현재 등록 내용 표시 | 선택 상태 |
| 3 | 하고 싶은 일을 입력 (예: "크롬 열어줘") | - | 입력칸 |
| 4 | 저장 | LLM(Ollama)이 `{action, target}`으로 해석 (최대 60초) | "해석 중" 표시 |
| 5-a | (성공) | 해석 결과를 `commands.json`에 저장 | 해석 결과(예: open_app / chrome) 표시, 토스트 |
| 5-b | (실패) | 저장하지 않음 | 실패 사유 안내 (Ollama 꺼짐, 시간 초과, 지원하지 않는 동작 등) |
| 6 | 해당 제스처를 수행 | 등록된 명령 실행 | 토스트: 실행 결과 |
| 7 | (선택) 목록에서 삭제 | 등록 내용 삭제 | 목록 갱신 |

등록할 수 있는 동작은 PC 제어 범위(화이트리스트)로 제한된다. 목록에 없는 앱·URL·단축키는 거부된다.

### S-4 음성 명령

경로가 둘이다. 어느 쪽이든 변환된 문장은 LLM이 해석해 1회성으로 실행하며 저장하지 않는다.

| 단계 | 경로 A: 웨이크워드 | 경로 B: 손등 유지 |
|---|---|---|
| 1 | "웨이크"라고 말함 (V-01) | 손등을 카메라에 보인 채 3초 유지 (H-10) |
| 2 | 시스템이 녹음 시작 | 시스템이 녹음 시작 |
| 3 | 명령을 말함 (예: "소리 꺼줘") | 손등 자세를 유지한 채 명령을 말함 |
| 4 | 말을 멈추고 1.2초 지나면 녹음 종료 | 손등 자세를 풀면 녹음 종료 |
| 5 | Whisper가 문장으로 변환 | Whisper가 문장으로 변환 |
| 6 | LLM이 해석, 허용 동작이면 실행 | LLM이 해석, 허용 동작이면 실행 |
| 7 | 토스트: 실행 결과 | 토스트: 실행 결과 |

녹음은 최대 15초이고 0.3초 미만의 녹음은 무시한다. 시끄러운 환경에서는 웨이크워드 대신 경로 B를 쓴다.

### S-5 창 닫기 확인

| 단계 | 사용자 행동 | 시스템 반응 | 화면 표시 |
|---|---|---|---|
| 1 | 손날(손을 세움)로 아래로 쓸어내림 | 닫기 요청 인식 (H-07) | 확인 팝업: "창을 닫을까요?" |
| 2-a | 엄지척 1초 유지 (또는 끄덕임, 팝업의 예 버튼) | 등록된 `close_confirm` 명령 실행, 없으면 활성 창 닫기 | 팝업 닫힘 |
| 2-b | 엄지다운 1초 유지 (또는 가로젓기, 팝업의 아니오 버튼) | 취소 | 팝업 닫힘, 토스트: "취소했습니다" |
| 2-c | 5초 동안 응답 없음 | 자동 취소 (안전 기본값) | 팝업 닫힘 |

확인 중에는 끄덕임·가로젓기가 예/아니오 응답으로만 쓰이고, 등록된 `nod`/`shake` 명령은 실행되지 않는다.

### S-6 포즈 모드 사용

| 단계 | 사용자 행동 | 시스템 반응 | 기능 ID |
|---|---|---|---|
| 1 | 양손을 모아 1초 유지 | 포즈 모드로 전환 (손 추적 꺼짐, 마우스 제어 중지) | H-11 |
| 2 | 카메라에서 떨어져 상체와 양팔이 보이게 앉음 | 상체 인식 시작 | P-01~P-04 |
| 3-a | 고개를 두 번 끄덕임 | 예 신호, 등록된 `nod` 명령 실행 | P-01 |
| 3-b | 고개를 두 번 좌우로 저음 | 아니오 신호, 등록된 `shake` 명령 실행 | P-02 |
| 3-c | 양팔을 옆으로 뻗어 ㅡ자로 1초 유지 | 전체 화면 캡처 저장 | P-04 |
| 4 | 다시 양손을 모아 1초 유지 | 손 모드로 복귀 | P-05 |

포즈 모드에서는 마우스 제어와 손 제스처가 동작하지 않는다. 전환 후 1.5초 동안은 다시 전환되지 않으며, 양손을 한 번 떼야 다시 전환할 수 있다.

### S-7 자리 비움 / 복귀

| 단계 | 사용자 행동 | 시스템 반응 | 화면 표시 |
|---|---|---|---|
| 1 | (포즈 모드) 카메라에서 벗어남 | 5초 이상 사람이 안 보이면 자리 비움 판정 | 토스트: "자리 비움 감지" |
| 2 | (자동) | 등록된 `away` 명령 실행 (예: 화면 끄기), 없으면 알림만 | - |
| 3 | 카메라 앞으로 돌아옴 | 자리 복귀 판정 | 토스트: "자리에 돌아왔습니다" |
| 4 | (자동) | 등록된 `back` 명령 실행 (예: 화면 켜기), 없으면 알림만 | - |

자리 비움 판정은 포즈 모드에서만 동작한다.

### S-8 인식 상태 확인

| 단계 | 사용자 행동 | 시스템 반응 | 화면 표시 |
|---|---|---|---|
| 1 | 트레이 메뉴 → 카메라 미리보기 켜기 | 확인용 카메라 창 열림 | 영상 + 랜드마크 점만 표시 (지표 없음) |
| 2 | 손 또는 몸을 움직여 점이 따라오는지 확인 | - | 점이 손/몸을 따라 움직임 |
| 3 | 트레이 메뉴 → 카메라 미리보기 끄기 | 창 닫힘, 인식은 계속 | 트레이 아이콘만 |

### S-9 일시정지 / 종료

| 단계 | 사용자 행동 | 시스템 반응 | 화면 표시 |
|---|---|---|---|
| 1 | 트레이 메뉴 → 일시정지 | 인식과 명령 실행 중지 | 트레이 아이콘 비활성 모양, 메뉴 항목이 "재개"로 변경 |
| 2 | 트레이 메뉴 → 재개 | 인식 재시작 | 기본 아이콘 |
| 3 | 트레이 메뉴 → 종료 | 카메라·마이크·스레드 정리 후 종료 | 트레이 아이콘 사라짐 |

### S-10 오류 상황

| 상황 | 시스템 반응 | 사용자 대응 |
|---|---|---|
| 카메라를 열 수 없음 | 토스트: "카메라를 찾을 수 없습니다", 트레이 아이콘 경고 모양 | 카메라 연결 확인 후 재실행 |
| Ollama가 꺼져 있음 | 명령 등록·음성 명령 실행 시 "Ollama가 실행 중이 아닙니다" 안내. 제스처 인식과 기본 동작은 계속 동작 | Ollama 실행 |
| GPU/CUDA 없음 | (예정) Whisper를 작은 모델·CPU로 전환하고 알림. 현재는 모델 로딩 단계에서 실패할 수 있음 | 안내에 따라 사용 |
| 마이크를 열 수 없음 | 음성 기능 사용 불가 알림. 손·포즈 기능은 계속 동작 | 마이크 연결 확인 |
| LLM이 해석하지 못함 | 실행하지 않고 사유 안내 | 표현을 바꿔 다시 말하거나 입력 |

## 3. 현재 실행 방식과의 차이

| 시나리오 | 현재(콘솔 + 카메라 창) | 설계안 |
|---|---|---|
| S-1 | 콘솔에 로딩 문구 출력, 카메라 창이 바로 열림 | 트레이 아이콘만, 완료 시 토스트 |
| S-3 | 콘솔에 `이름: 내용` 입력 | 설정창에서 선택 + 입력 |
| S-5 | 콘솔 로그로 "창을 닫을까요?" 안내 | 확인 팝업 |
| S-7 | 콘솔 로그, 명령이 있을 때만 실행 | 토스트 + 명령 실행 |
| S-8 | 카메라 창이 항상 열려 있고 지표가 겹쳐 표시 | 점만 표시, 필요할 때만 열기 |
| S-9 | 카메라 창에서 `q`로 종료, 일시정지 없음 | 트레이 메뉴 |

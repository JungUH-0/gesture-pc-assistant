# 개인 AI 비서 (Gesture · Voice · LLM Assistant)

웹캠과 마이크로 **손동작 · 전신 포즈 · 음성**을 인식해서 PC를 제어하는 개인 비서.
실행할 명령은 **로컬 LLM(Ollama)** 이 자연어로 해석하므로, 코드를 고치지 않고
"메모장 열어줘" 같은 문장만으로 제스처에 원하는 동작을 새로 지정할 수 있다.

모든 처리(포즈 인식 · 음성 인식 · LLM 해석)가 **로컬에서** 돌아가며 외부 서버로
나가는 데이터가 없다.

---

## 구조

```
[모드 A] cameramodule.py (손동작 인식) ─┐
                                        ├→ main.py ─→ commandmodule.py ─→ windowcontrol.py
[모드 B] posemodule.py   (전신 포즈)  ─┘  (모드 전환)   (LLM 해석 + 실행)     (실제 OS 동작)
                                             ↑
                          voicemodule.py (음성) ┘
                          audiomodule.py (박수 - 모드 전환 신호)
```

**설계 원칙**

- **인식과 실행의 분리** — 인식 모듈은 "무슨 동작인지"만 판정해서 이름으로 보고하고,
  실제로 무엇을 실행할지는 `main.py`가 `commandmodule`을 통해 결정한다. 덕분에
  사용자가 제스처에 다른 명령을 등록해도 인식 코드를 건드릴 필요가 없다.
- **명령 엔진 공유** — 손동작 · 전신 포즈 · 음성 세 입력이 `commandmodule` 하나를
  공유한다. 명령 종류를 추가하면 세 입력 모두에 동시에 적용된다.
- **한 번에 한 인식기만** — 손 인식과 포즈 인식을 동시에 돌리면 FPS가 떨어지고
  제스처끼리 충돌하므로, 모드를 나눠 한쪽만 실행한다.
- **화이트리스트 실행** — LLM이 만들어낸 문자열을 그대로 실행하지 않고, 미리
  등록된 동작 목록에 있는 것만 실행한다.

## 폴더 구성

| 위치 | 용도 |
|---|---|
| 루트의 `*.py` | **실험용** — 인식 규칙과 임계값을 바꿔 보고 검증하는 곳. 콘솔로 실행한다 |
| `app/` | **프로그램(트레이 앱) 제작용** — 루트 모듈을 복사해 UI 앱으로 발전시키는 곳. 실험 코드와 섞이지 않는다 |
| `docs/` | 프로젝트 문서 (개요 · 기능명세서 · 메뉴 구조 · 유저흐름도). [문서](#문서) 참고 |

## 기능

### 손동작 모드 (기본)

| 제스처 | 동작 |
|---|---|
| 손바닥 중심점 이동 | 마우스 커서 이동 (떨림 보정 + 감도 증폭) |
| 엄지 + 검지 붙이기 | **좌클릭** — 붙이면 누름, 떼면 뗌 (클릭·드래그 모두 가능) |
| 엄지를 손바닥 중앙으로 넣기 | **우클릭** |
| 약지·새끼 말고 손 전체 위/아래 | **휠 스크롤** |
| 주먹 + 엄지 위 (1초 유지) | **예 / 동의** |
| 주먹 + 엄지 아래 (1초 유지) | **아니오 / 거절** |
| 스와이프 업 | 창 복원 *(커스텀 명령 등록 시 대체)* |
| 스와이프 다운 | 창 최소화 *(커스텀 명령 등록 시 대체)* |
| **손날** + 스와이프 다운 | 창 닫기 **확인 요청** → 예/아니오로 확정 |
| 엄지 + 중지 / 약지 / 새끼 | **커스텀 명령 슬롯 3개** |
| 손등 3초 유지 | **음성 명령 녹음 시작** |

> 클릭류(좌·우클릭, 커스텀 슬롯)는 손이 **정면(손바닥)** 일 때만 판정된다.
> 손등·손날 방향에서는 카메라의 2D 투영 때문에 손가락이 겹쳐 보여 오작동하기 때문.

### 전신 포즈 모드

상체 9개 키포인트(코 · 귀 · 어깨 · 팔꿈치 · 손목)를 인식해 **22차원 특징**을 추출한다.
어깨 중점을 원점, 어깨 너비를 스케일로 삼아 정규화하므로 **화면상 위치와 카메라
거리에 영향을 받지 않는다.**

| 특징 | 구성 |
|---|---|
| 정규화 좌표 | 9개 × (x, y) = 18 |
| 팔꿈치 각도 | 좌 · 우 = 2 (0=굽힘, 1=폄) |
| 머리 방향 | 돌리기 · 기울이기 = 2 |

**사용자가 자세를 등록하는 기능은 아직 미구현** — 현재는 특징 추출과 시각화까지만 동작한다 (계획은 아래 [현재 상태 / 다음 단계](#현재-상태--다음-단계)).

**고개 동작 (예 / 아니오)**

| 동작 | 판정 | 신호 |
|---|---|---|
| 두 번 끄덕임 | 2초 안에 위아래로 두 번 | **예** |
| 두 번 가로젓기 | 2초 안에 좌우로 두 번 | **아니오** |

- 한 번만 숙이거나 돌린 것은 인정하지 않는다. 끄덕임에는 좌우 움직임이, 가로젓기에는 위아래
  움직임이 섞이면 거부한다 (대각선 움직임 제외).
- 팔꿈치·손목이 가려져 특징 추출이 실패한 프레임에서도 판정한다. 필요한 것은 어깨와 코·귀뿐이다.
- 임계값(`posemodule.py`의 `HEAD_*` 상수)은 **추정치이며 실측 전**이다.
  `debug_pose.txt`의 `headPitch` / `headTurn` 값을 보고 조정한다.

**자리 비움**

사람이 5초 이상 화면에서 보이지 않으면 `away`, 다시 보이면 `back` 이벤트가 발생한다.
`commandmodule`에 `away` / `back` 이름으로 명령을 등록해 두면 실행되고(예: 모니터 끄기 / 켜기),
등록이 없으면 로그만 남긴다.

**끄덕임 · 가로젓기에 명령 연결**

`nod` / `shake` 이름으로 명령을 등록해 두면 끄덕이거나 가로저을 때 실행된다. 등록이 없으면 로그만
남긴다. 창 닫기 확인 중에는 예 / 아니오 응답으로만 쓰이고 등록된 명령은 실행되지 않는다.

**화면 캡처 (ㅡ자 자세)**

양팔을 옆으로 쭉 뻗어 어깨 높이에 일직선이 되게 **1초 유지**하면 전체 화면을 실행 폴더의
`captures/` 에 PNG로 저장한다 (저장 뒤 3초간은 다시 인식하지 않는다).
손목·팔꿈치가 어깨 높이에서 어깨 너비의 0.4배 이내이고, 손목이 어깨보다 바깥으로 어깨 너비 이상
나가 있어야 한다. 값은 `posemodule.py`의 `T_POSE_*` 상수이며 **실측 전**이다
(인식이 되는 것까지만 확인).

**포즈 모드만 따로 확인하기**

```bash
python pose_check.py
```

카메라와 포즈 모듈만 연결해 끄덕임 · 가로젓기 · 자리 비움 · ㅡ자 자세를 콘솔에 출력한다.
음성이나 PC 제어는 띄우지 않으므로 임계값을 조정하며 반복 확인하기에 편하다.

**진단 스크립트**

| 스크립트 | 용도 |
|---|---|
| `perf_check.py` | 카메라만 / 오디오 추가 / 음성 추가 구간별 FPS 측정 — 프레임이 떨어지는 원인 확인 |
| `hands_check.py` | 양손 검출 비율과 두 손 중심 거리, 끊김 없이 이어진 "양손 모임" 구간 측정 — 모드 전환이 안 될 때 확인 |

### 모드 전환

**양손을 모아 1초 유지**하면 손동작 ↔ 전신 포즈 모드가 전환된다.
(`main.py`의 `MODE_SWITCH_REQUIRE_CLAP = True`로 바꾸면 "박수 + 양손 모임"을 요구하는
방식으로 되돌릴 수 있다. 소음이 심한 환경을 고려해 기본값은 박수 없이 동작.)

### 음성 명령

| 트리거 | 녹음 종료 |
|---|---|
| **"웨이크"** 발화 | 말이 끝나고 1.2초 무음이면 자동 종료 |
| **손등 3초 유지** | 손을 떼는 순간 종료 (무전기 방식) |

Whisper(`medium`, GPU)로 텍스트 변환 → LLM 해석 → 즉시 실행. 음성 명령은 제스처
슬롯에 등록할 필요 없이 그때그때 자유롭게 말하면 된다.

### LLM이 실행할 수 있는 동작

| 분류 | 목록 |
|---|---|
| 창 제어 | 최소화 / 닫기 / 복원 |
| 모니터 | 끄기 / 켜기 |
| 앱 실행 | chrome, edge, notepad, calculator, explorer, cmd, powershell |
| 단축키 | copy, paste, cut, undo, redo, save, select_all, new_tab, close_tab, switch_window |
| 미디어 키 | volume_up/down, mute, play_pause, next_track, prev_track |
| 사이트 열기 | youtube, google, gmail, naver, github |
| 웹 검색 | `search_web` — "날씨 검색해줘"처럼 검색어를 구글 검색으로 연다 (기본 브라우저) |

## 설치

**환경**: Windows (win32 API 사용), Python 3.10, NVIDIA GPU 권장 (Whisper용)

```bash
pip install mediapipe opencv-python numpy pillow pywin32 sounddevice requests faster-whisper pystray
```

| 패키지 | 확인된 버전 | 용도 |
|---|---|---|
| mediapipe | 0.10.9 | 손 · 얼굴 · 포즈 랜드마크 |
| opencv-python | 5.0.0.93 | 카메라 입출력, 시각화 |
| numpy | 2.2.6 | 수치 연산 |
| pillow | 12.3.0 | 화면 한글 텍스트 렌더링 |
| pywin32 | 312 | 마우스 · 키보드 · 창 제어 |
| sounddevice | 0.5.5 | 마이크 입력 |
| requests | 2.34.2 | Ollama API 호출 |
| faster-whisper | 1.2.1 | 음성 인식 |
| pystray | 0.19.5 | 트레이 아이콘 (`app/` 트레이 앱 전용) |

**Ollama 설치 및 모델 준비**

```bash
winget install --id Ollama.Ollama -e
ollama pull qwen2.5:3b-instruct
```

Whisper 모델(`medium`, 약 1.5GB)은 최초 실행 시 자동으로 내려받는다.

## 실행

### 콘솔 실행 (루트 폴더, 실험용)

```bash
python main.py
```

카메라 창에서 `q`를 누르면 전체 종료.

**손이 오래 안 보이면 로그 생략** — 손 모드에서 손이 3초 이상 보이지 않으면(손을 내리고
키보드를 치는 중 등) 제스처 · 마우스 · 신호 로그를 찍지 않는다. 손이 다시 보이면 바로 재개되고,
모드 전환 · 음성 · 등록 로그는 계속 나온다. 제스처 처리 자체는 그대로 동작한다
(`main.py`의 `HAND_GONE_QUIET_SEC`).

**제스처에 명령 등록하기**

방법 1 — `main.py` 실행 중에 터미널에 바로 입력 (`이름: 하고 싶은 일`)

```
pinch_ring: 크롬 열어줘
```

방법 2 — 별도 실행

```bash
python commandmodule.py
```

1. 제스처 이름 입력 (`pinch_middle`, `pinch_ring`, `pinch_pinky`, `swipe_up`, `swipe_down`, `close_confirm`, `away`, `back`, `nod`, `shake`)
2. 하고 싶은 일을 자연어로 입력 (예: `"유튜브 열어줘"`)
3. LLM이 해석해서 `commands.json`에 저장

`main.py`가 실제로 호출하는 이름은 위 목록뿐이다. 다른 이름으로 저장하면 저장은 되지만 실행되지 않으며,
`main.py`의 콘솔 등록에서는 경고가 표시된다.

`commands.json`은 실행 중에도 매번 다시 읽으므로 **`main.py` 재시작 없이 바로 반영**된다.
항목을 지우거나 파일을 통째로 삭제해도 안전하며, 같은 이름으로 다시 등록하면 덮어쓴다.
저장 형식은 `commands.example.json`을 참고한다.

### 트레이 앱 (`app/`)

콘솔 창과 카메라 창 없이 **시스템 트레이 아이콘**으로만 상주한다. 모델 로딩이 끝날 때까지는
주황색, 실행 중에는 파란색, 일시정지에는 회색, 중지(카메라 오류 등)에는 빨간색 아이콘이 표시된다.

```bash
cd app
pythonw tray_main.py
```

`pythonw`로 실행해야 콘솔 창이 뜨지 않는다. 콘솔 출력은 모두 `app/logs/assistant.log`에 기록되며,
같은 앱을 두 번 켜면 두 번째는 바로 종료된다 (카메라 · 마이크 충돌 방지).

| 트레이 메뉴 | 동작 |
|---|---|
| 카메라 미리보기 | 확인용 카메라 창을 켜고 끈다. 창에서 `q`를 누르거나 X로 닫아도 앱은 종료되지 않고 미리보기만 닫힌다 |
| 설정 | 설정창을 연다 (아래 참고) |
| 로그 보기 | 로그 파일을 연다 |
| 일시정지 / 재개 | 일시정지 중에는 인식 · 마우스 제어 · 명령 실행 · 웨이크워드 검사를 모두 멈춘다 (아이콘 회색) |
| 종료 | 정리 후 종료 |

**설정창** — 트레이 메뉴의 "설정"으로 연다 (이미 열려 있으면 앞으로 가져온다).

| 탭 | 내용 |
|---|---|
| 명령 등록 | 동작 이름을 목록에서 고르고 "하고 싶은 일"을 자연어로 입력해 저장한다 (Enter로도 저장). LLM이 해석하는 동안 "해석 중..."이 표시되고, 끝나면 해석 결과(예: `open_app · chrome`)가 상태 줄과 알림에 나온다. 아래 목록에서 등록된 명령을 확인하고, 명령을 골라 "선택한 명령 삭제"로 지운다 |
| 음성 | 음성 명령 사용 켜기 / 끄기. 끄면 웨이크워드 감지와 손등 3초 트리거가 모두 멈춘다 |
| 일반 | **개발 모드** — 카메라 미리보기에 랜드마크 점 · 선과 함께 FPS · 모드 · 판정 수치 등 지표를 표시한다 |

설정은 `app/settings.json`에 저장되어 다음 실행에도 유지된다. 카메라 미리보기는 기본이 **일반 모드**라
랜드마크 점과 연결선만 보이고, 오인식 원인을 찾을 때는 개발 모드를 켠다. 앱을 오래 켜 두었다가 처음
명령을 저장하면 Ollama 모델이 메모리에 올라오는 동안 60초 제한을 넘겨 실패할 수 있는데, 한 번 더 저장하면 된다.

**알림** — 모드 전환, 자리 비움 / 복귀, 화면 캡처 저장(경로 표시), 음성 명령 듣는 중 · 실행 결과,
명령 저장 결과가 윈도우 알림으로 표시된다. 처음 실행하면 사용법을 한 번 알리고, Ollama가 꺼져 있거나 모델이 없으면
실행할 때마다 안내한다. 알림은 윈도우 설정을 그대로 따르므로 **방해 금지가 켜져 있으면 배너가 뜨지 않는다**
(알림 센터에는 쌓인다).

**창 닫기 확인 팝업** — 손날 + 스와이프 다운 시 화면 오른쪽 아래에 "창을 닫을까요?" 팝업이 뜬다.
버튼(예 / 아니오)이나 제스처(엄지척 · 끄덕임 / 엄지다운 · 가로젓기)로 5초 안에 응답한다.
팝업은 포커스를 가져가지 않으며, 확인을 **시작한 순간의 활성 창**을 닫는다.

**루트(실험용)와 다른 점**

- 양손 모임 기준을 0.15에서 **0.20**으로 완화했고, 손이 맞닿아 MediaPipe가 한 손을 놓쳐도 마지막 2초
  안에서는 모임을 이어서 본다 (겹친 손이 한 손으로 보여 유지 시간이 계속 초기화되던 문제).
- 모드 전환 직후 **5초** 동안은 다시 전환하지 않는다 (루트는 1.5초).
- 명령은 `app/commands.json`에 따로 저장된다. 루트에서 등록한 명령은 이어지지 않는다.
- 카메라 미리보기는 기본이 점 · 선만 보이는 일반 모드다. 루트와 `app/`을 콘솔로 실행(`python main.py`)하면
  예전처럼 지표를 전부 표시한다.

## 다른 PC에서 실행하기

```bash
git clone https://github.com/JungUH-0/gesture-pc-assistant.git
cd gesture-pc-assistant
```

코드는 clone하면 그대로 따라오지만 아래는 **git에 없으므로 직접 준비**해야 한다.

| 항목 | 이유 | 할 일 |
|---|---|---|
| 파이썬 환경 | git에 안 들어감 | `pip install -r requirements.txt` (Python 3.10) |
| Ollama + 모델 | 별도 프로그램 | `winget install Ollama.Ollama`, `ollama pull qwen2.5:3b-instruct` |
| Whisper `medium` (약 1.5GB) | 자동 다운로드 | 첫 실행 때 받음 |
| `commands.json` (`app/`에도 별도) | `.gitignore` 대상 | 등록한 제스처 명령이 사라지므로 `python commandmodule.py`로 다시 등록 |
| `debug_*.txt` · `app/logs/` | `.gitignore` 대상 | 실행하면 다시 생성됨 |

**막힐 수 있는 지점**

- **Windows 전용** — `pywin32`로 마우스·키보드·창을 제어하므로 Mac·Linux에서는 동작하지 않는다.
- **GPU가 없으면 음성 인식이 느리거나 실패한다** — `voicemodule.py`의
  `WhisperModel(MODEL_SIZE, device="cuda", compute_type="float16")` 가 CUDA 고정이다.
  GPU가 없으면 `device="cpu", compute_type="int8"` 로 바꾸고, `MODEL_SIZE`도 `small` 이하로 낮추는 게 좋다.
- **카메라 번호** — `main.py`의 `CameraModule(camera_id=0, ...)`. 카메라가 여러 개면 번호를 바꿔야 할 수 있다.

## 현재 상태 / 다음 단계

**미완성**

- **사용자 포즈 등록** — 특징 추출까지만 되어 있고 등록 · 인식이 없다. 설정창 포즈 탭에서 자세를 촬영해 등록하고
  템플릿 비교로 인식하는 방식으로 설계했다 (아래 다음 단계 참고)
- 눈 관련 기능 — 블링크 · 롱블링크(모니터 끄기) 등은 주석 처리 상태이고, EAR 계산(얼굴 인식)도
  기본으로 꺼져 있다 (`cameramodule.py`의 `EYE_TRACKING_ENABLED = False`). 켜 두면 매 프레임 얼굴 인식이
  같이 돌아 FPS가 떨어지기 때문이다. 개인차가 커서 우선순위를 뒤로 미룸
- **트레이 앱 직접 확인 대기** — `app/` 트레이 앱은 구조 정리 · 트레이 아이콘과 메뉴 · 알림과 확인 팝업 ·
  설정창 · 일반/개발 모드까지 만들었다. 트레이, 알림, 확인 팝업(예 / 아니오)은 직접 확인했지만, 설정창의
  명령 저장 · 삭제와 음성 설정 유지, 일반 모드에서 손 랜드마크가 그려지는지는 사용하면서 확인할 차례이다
  (명령 저장·삭제 로직 자체는 임시 파일로 검증했다)
- **설정창 2차 항목 미구현** — 웨이크워드 변경, 캡처 저장 폴더, 시작 시 자동 실행, 임계값 조정은 필요해지면
  추가한다. 오류(카메라 없음 등)는 아이콘 색과 로그로만 알리고 알림은 아직 없다
- 웨이크워드 **"웨이크"는 임시값** — 확정 전이며 `voicemodule.py`의 `WAKE_WORD`에서 바꾼다
- **음성 명령 실사용 테스트 대기** — 트리거와 로그까지만 확인했고, 녹음한 음성 파일로
  Whisper → LLM → 실행 전체 경로는 아직 검증하지 않았다
- **포즈 동작 임계값 실측 대기** — 끄덕임 · 가로젓기 · 자리 비움은 구현되어 있으나 `HEAD_*` 값은
  추정치이다. ㅡ자 캡처(`T_POSE_*`)도 인식이 되는 것까지만 확인했다. `pose_check.py`로 반복 확인하고
  `debug_pose.txt`로 조정할 예정
- **GPU가 없는 PC 대응 미구현** — Whisper가 CUDA 고정이라 GPU가 없으면 모델 로딩 단계에서 실패할 수 있다.
  작은 모델 · `int8`로 내려가는 CPU 폴백이 필요하다
- 이 PC에서 측정한 프레임은 음성을 켜도 평균이 유지되었으나(약 29에서 31 FPS) 순간 최저가 6.4까지 떨어진
  적이 있고, 다른 환경에서 끊김이 보고된 적이 있어 **원인은 확정하지 못했다** (`perf_check.py`로 측정)
- IoT(홈캠 연동)는 의도적으로 보류

**다음 단계 (사용자 포즈 등록)**

지금 포즈 모드의 입력은 끄덕임 · 가로젓기 · ㅡ자처럼 **코드에 정해 둔 것**뿐이다. 사용자가 **자세 자체를 직접 등록**해서
새 입력으로 쓸 수 있게 만든다 (설계 합의 완료, 구현 전).

1. 등록 — 설정창에 **포즈 탭**을 추가한다. 이름을 입력하고 촬영을 누르면 카운트다운 뒤 약 2초 동안 자세를 유지한
   프레임의 22차원 특징(어깨 너비 기준 정규화라 거리 · 위치와 무관)을 저장한다
2. 인식 — **학습 없이 템플릿 비교**로 한다. 현재 특징이 등록한 자세와 가까운 상태가 1초 유지되면 그 자세 이벤트가
   발생한다. 처음 계획했던 XGBoost / SVM / kNN 학습 대신 이 방식을 택한 이유는, 사용자가 몇 초 만에 등록하고 바로 써야
   해서 모델을 돌리는 단계가 맞지 않기 때문이다
3. 연결 — 포즈 이름이 `명령 등록` 탭의 동작 이름 목록에 `pose_이름`으로 나타나고, 기존처럼 자연어로 하고 싶은 일을
   저장해 연결한다. 포즈 탭에서는 이름 · 촬영 · 삭제만 한다

**범위와 한계**

- **정지 자세만** 다룬다 (몇 초 유지하는 자세). 움직임이 있는 동작은 이번 범위가 아니다. ㅡ자 캡처는 지금처럼 내장 기능으로 둔다
- 쓰는 것이 상체 키포인트 9개(코 · 귀 · 어깨 · 팔꿈치 · 손목)라 **손가락 모양과 하체 자세는 구분하지 못한다.** 팔을 올리는 높이,
  팔꿈치 굽힘, 고개 방향 정도의 차이는 구분할 수 있다
- 비슷한 자세는 서로 헷갈릴 수 있어서 등록할 때 기존 자세와 너무 비슷하면 경고할 계획이다. 인식 거리 기준값은 실측으로 조정해야 한다
- `app/`에서만 만든다 (루트의 실험용 코드는 건드리지 않음)

개발 과정의 요구사항과 설계 판단 근거는 [DEVLOG.md](DEVLOG.md) 참고.
